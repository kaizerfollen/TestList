# Frontend Hiring Test — Vue.js

Мини-проект на Vue 3 из двух блоков: **А** (доработка фичи) и **Б** (код-ревью).

**Время:** 3–4 часа  
**Требование:** Node 18+

---

## Запуск

```bash
npm install
npm run dev     # приложение на http://localhost:5173
npm run build   # сборка должна проходить без ошибок
```

Список пользователей загружается из mock-API с задержкой ~750 мс. Файл блока Б в сборке не участвует — он нигде не импортируется.

---

## Блок А: Доработать фичу

**Что дано:**
- `src/App.vue` — наивный стартер: просто рендер всех пользователей из mock-API
- `src/api/mock.js` — mock-API, возвращающий список юзеров с задержкой
- `src/api/users.js` — данные (id, name, email, role, status)

**Что добавить:**
1. **Фильтр/поиск** по списку (по имени, email, роли или статусу — на выбор).
2. **Корректная обработка состояний:**
   - Loading: показать индикатор во время загрузки.
   - Error: если произойдёт ошибка загрузки, показать сообщение об ошибке.  
     *(Подсказка: переключи флаг `SIMULATE_ERROR = true` в `src/api/mock.js`, чтобы проверить обработку ошибки.)*
3. **Декомпозиция на компоненты** — раздели код на компоненты так, как считаешь правильным, и обоснуй разбиение в своём README-ответе.

**Definition of Done (блок А):**
- Фильтр/поиск работает
- Loading-состояние показывается явно
- Error-состояние обрабатывается и показывается
- Компоненты аккуратно разделены

## Блок Б: Код-ревью

**Что это:**
Файл `review/ReviewMe.vue` — отдельный сниппет, **не часть приложения**, не запускается.

**Задача:**
Прочитай код и опиши письменно:
- Какие проблемы видишь?
- Как каждую чинить?

**Формат ответа:**
Создай файл `REVIEW.md` или секцию в своём README-ответе с анализом проблем и рекомендациями по улучшению кода.

---

## Правила по использованию ИИ

**Ты можешь использовать ИИ** (ChatGPT, Claude, Copilot, etc.) для блока А, но:
- Не копируй решение одним куском — разберись, как оно работает.
- Все правки, которые ты сделал руками (переписал, исправил, вырезал), отметь в AI-log.

**Блок Б — проверка, что ты видишь косяки** (в том числе в ИИ-сгенерированном коде). Если ты применял ИИ в блоке Б, **обязательно отметь это в AI-log**.

**AI-log обязателен** (в любом виде). Два способа на выбор:

- **(A)** заполнить таблицу ниже своими словами; **или**
- **(B)** приложить сырой лог сессии из своего инструмента (ChatGPT-share / Claude Code / Cursor history и т.п.) — файлом или ссылкой. Если выбираешь (B), добавь сверху 2–3 строки: где ИИ был решающим и что ты отклонил/переделал.

Отсутствие лога или «ИИ написал всё, я не смотрел» — сигнал против кандидата. Если ИИ не использовал — так и напиши.

### Шаблон AI-log (вариант A)

Таблица — в `AI-LOG.md` или секцией в твоём ответе. Пример строки ниже — **формат** (на постороннем коде, не из этого задания):

| Где использовал | Промпт (кратко) | Что переписал руками и почему |
|---|---|---|
| (пример формата) | «сгенерируй функцию форматирования даты» | Взял основу, переписал под нужный формат и локаль, убрал лишнюю зависимость. |

## Что сдать

1. **Репозиторий** (GitHub / архив) с кодом блока А + файл блока Б (`REVIEW.md`).
2. **README-обоснование** (в корне репо или отдельным файлом) — 1–2 абзаца про декомпозицию компонентов: почему разделил именно так.
3. **Файл `REVIEW.md`** — разбор проблем, которые найдёшь в `review/ReviewMe.vue` (сколько их — реши сам). По каждой: в чём проблема и как чинить.
4. **AI-log** — заполненная таблица (в `AI-LOG.md` или README) **либо** приложенный сырой лог сессии + 2–3 строки рефлексии (см. раздел про ИИ выше).
